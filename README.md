# BiddingAnalysis

盘前竞价系统

**在线地址：https://aimi-ding.github.io/BiddingAnalysis/**

> 基于原有「网页版竞价.html」构建。**选股、筛选、打分逻辑与原文件完全一致，未做任何改动。**
> 只增加了两个附加功能：每日快照记录、收盘后自动复盘。

1. **每日快照**：交易日 9:25:30 自动把主页显示的内容存一份

这两个功能**不参与选股**，只是记录和统计。

## 二、数据来源

唯一接口：

```
https://push2dycalc.eastmoney.com/api/qt/clist/get
```

- HTTPS 证书签发给 `O=East Money Information Co., Ltd.`，属东方财富官方
- 与腾讯、新浪行情交叉核对一致
- 免费、无需 key、无需登录

**但它是东财网页前端自用的内部接口**，没有文档、没有可用性承诺，字段可能变、高频访问可能被限流。

### 字段含义

| 字段 | 含义 | 字段 | 含义 |
|---|---|---|---|
| f2 | 最新价 | f12 | 代码 |
| f3 | 涨跌幅 % | f14 | 名称 |
| f4 | **涨跌额** | f615 | 竞价涨幅 % |
| f5 | 成交量（手） | f17 | 今开 |
| f10 | **量比** | f18 | 昨收 |

### 时间限制

`f615`（竞价涨幅）只在 9:15–9:25 集合竞价期间产生，之后冻结。
所以这个看板**只有早上竞价时段打开才有意义**。

## 三、每日快照

### 存什么

**存的就是主页此刻显示的内容**，不做任何额外筛选：

```
左侧榜 = 主页左栏那 3 张卡片
右侧榜 = 主页右栏的候选列表（不只是屏幕上显示的那几只）
```

抓取时会重新拉一次行情并刷新页面，所以**存下来的和页面上看到的一定一致**（已实测：84 只对 84 只，逐字段相同）。

### 什么时候抓

```
交易日 9:25:30 – 9:29:59   自动抓一次
周末                        跳过
```

> 为什么是 9:25:30 而不是 9:25:00：竞价刚结束时接口的 `f615` 可能还没定型，留 30 秒缓冲。

**页面必须在 9:25:30 前打开。** 过了这个窗口，手动点「立即抓取」也能存，但成交量字段已不是竞价量。

### 数据在哪

存在浏览器 **IndexedDB**（数据库名 `auction_snapshots`）。

点面板「查看数据」可以看到每个交易日的记录，点某一天进入明细：

```
左侧榜（主页左栏）
#  代码     名称     竞价涨幅   涨停率  可信度
1  002086  东方海洋  +4.40%    64%    76%

右侧榜（主页右栏）
#  代码     名称     竞价涨幅   实时涨幅  涨速  涨停率  可信度  行业
```

点「导出」可以把全部快照和复盘数据下载成 JSON 备份。

## 四、每日复盘

### 规则

```
样本    当天快照里记录的那批（= 主页 9:25:30 那一版）
买入    当日开盘价
卖出    当日收盘价
收益    (收盘价 / 开盘价 - 1) × 100%
成功率  收盘价 > 开盘价 的只数 ÷ 样本数
```

**涨标红、跌标绿。**

### 什么时候跑

```
交易日 15:00–16:00   自动执行一次
周末                 跳过
节假日               全市场数据不足 3000 只 → 判为非交易日，跳过
```

盘中手动点「重新生成」拿到的是盘中价，系统会记下生成时段，**收盘后自动重算覆盖**。

### 怎么看

点面板「复盘」：

```
成功率（大字）
涨 N 只　跌 N 只　平 N 只　共 N 只
平均收益 +X.XX%
复盘对象：主页 HH:MM:SS 那批
```

下面是逐只明细表，顶部下拉框切换历史日期。

### 一个重要提醒：成功率会偏高

主页的筛选条件里有 `f4 > 0`，即「当前涨跌额为正」。

在竞价时段（9:25:30），`f4` 恰好等于竞价涨幅，所以筛出来的是「竞价上涨」的股票。
但**复盘是收盘后跑的，此时 `f4` 已经变成「今日涨跌额」**——被选进快照的股票，都是当时还在涨的。

再加上收盘后统计，这些股票天然更容易是涨的。

**实测某日下午（普涨行情）：85 只里 84 只涨，成功率 98.8%。**

这不是数据错误，是筛选条件带来的幸存者偏差。**看复盘数据时要知道这一点：成功率反映的是「已选中标的的表现」，不是「竞价策略的无偏胜率」。**

## 五、怎么用

### 在线版

https://aimi-ding.github.io/BiddingAnalysis/

免安装，功能一致。**快照数据存在浏览器本地，换浏览器或清缓存会丢，记得定期点「导出」备份。**

### 本地版

```bash
cd auction-screener
python3 -m http.server 8899
# 打开 http://127.0.0.1:8899/index.html
```

### 日常操作

```
交易日 9:20 前    打开页面
9:25:30          自动记录主页数据，不用管
9:30 之后         看选股结果
15:00 之后        自动复盘，点「复盘」看结果
```

## 六、已知特性（原版行为，未改动）

以下这些看起来像问题，但**是原文件本来的逻辑，按要求原样保留**：

| 现象 | 原因 |
|---|---|
| 左侧「成交额」一项没有区分度 | 读 `stock.f20`，但请求字段里没有 f20，恒为 0 |
| 「剔除昨日涨停」实际没生效 | `getYesterdayChange` 用 f4 当昨收算，结果恒为负，判断永不触发 |
| 右侧「流通市值」因子失效 | 读 `stock.f10`，但 f10 是量比，不是流通市值 |
| 右侧总分天然偏低 5 分 | 五项权重和是 0.95，不足 1 |
| 表格「涨速」列显示的是量比 | 取 `s.f10`，实际是量比 |
| 界面有「AI智能研判」字样 | 代码里没有任何模型参与，是手工加权求和 |

**这些都不影响快照和复盘的正确性**——它们只是记录和统计，不改选股逻辑。
