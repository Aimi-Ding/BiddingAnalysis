# 回测报告：竞价选股策略到底有没有用

**结论先说：按现有逻辑（买竞价高开、按竞价涨幅越高越好排序），在 500 个交易日、全市场 5565 只股票的样本上，没有超额收益，而且是双重跑输。**

具体数字：日均比全市场低 **0.26 个百分点**，跑赢基准的交易日只有 **47.6%**（低于一半）。

下面是完整证据。

---

## 一、数据与方法

### 数据

```
样本    全市场 5,565 只（沪主板+深主板+创业板+科创板）
区间    最近 500 个交易日（约 2 年）
来源    东方财富日线接口，前复权
有效    464 个交易日（每日有效样本 ≥ 1000 只才计入）
```

抓取方式见 `fetch_daily.py`，数据不入库（`backtest/data/` 已 gitignore），可随时重跑。

### 为什么能重建「竞价涨幅」

东财没有历史竞价快照（`f615` 只反映实时值）。但**集合竞价的结果就是开盘价**，所以：

```
历史竞价涨幅 = (当日开盘价 / 前一日收盘价 - 1) × 100%
```

这是精确重建，不是近似。

### 收益口径（这里踩过一个坑）

**A股 是 T+1，当天买入当天不能卖。** 所以：

```
买入   D 日开盘价（= 集合竞价成交价）
卖出   D+1 日收盘价        ← 可执行
参照   D 日收盘价          ← T+1 下不可执行，仅作对照
```

如果按「当日开盘买、当日收盘卖」算，前 3 名日均 -1.05%，看起来更糟——但那个操作根本做不了，不能用来下结论。

### 必须剔除的

| 剔除项 | 数量 | 原因 |
|---|---|---|
| 竞价下跌 | 1,191,270 | 原策略要求 f4>0（只买高开） |
| ST / 退市 | 106,533 | |
| 开盘涨停 | 5,001 | **一字涨停买不进**，不剔除会严重虚高 |
| 开盘跌停 | 2,017 | |
| 无次日数据 | 130 | 无法计算 T+1 收益 |

涨停幅度按板块判定：创业板/科创板 20%，主板 10%，北交所 30%，ST 5%。

---

## 二、核心结果

### 1. 策略本身：跑输

| 口径 | 日均收益 | 胜率 | 日均超额 | 跑赢基准天数 |
|---|---|---|---|---|
| 前 3 名（不限竞价涨幅） | -0.478% | 46.6% | **-0.535%** | 47.6% |
| 前 3 名（竞价涨幅 <7%） | -0.098% | 47.2% | **-0.155%** | 47.0% |
| 前 3 名（竞价涨幅 <9.5%） | -1.095% | 41.8% | **-1.153%** | 42.9% |
| 前 10 名（<7%） | -0.038% | 48.3% | -0.095% | 48.1% |

**三个口径全部为负超额，且跑赢基准的天数都不到一半。** 这不是运气问题，是系统性跑输。

### 2. 问题出在哪：筛选条件本身就是负的

把基准拆开看：

```
全市场等权（含低开的股票）    日均 +0.1663%
只留「竞价上涨」的股票        日均 +0.0667%
                            ─────────────
差                          -0.0996%
```

**光是把「竞价下跌」的股票剔除掉，就比全市场差了 0.1%/天。** 这是原策略第一个筛选条件（`f4 > 0`）带来的损失。

在这个基础上再按竞价涨幅排序取前 3，又损失 0.16%/天，合计跑输全市场 **0.26%/天**。

**换句话说：这个策略的两个核心设计（只买高开 + 越高越好）都是负向的。**

### 3. 真正的规律是倒 U 型，不是单调递增

按竞价涨幅分档，看每一档的 T+1 收益（464 个交易日，280 万样本）：

| 竞价涨幅 | 样本数 | 日均收益 | 胜率 |
|---|---|---|---|
| 0~1% | 1,039,910 | +0.125% | 47.8% |
| 1~2% | 157,392 | +0.208% | 47.4% |
| **2~3%** | 48,029 | **+0.337%** | 47.9% |
| 3~5% | 27,951 | +0.306% | 46.6% |
| 5~7% | 8,681 | +0.171% | 46.4% |
| **7~10%** | 4,409 | **-0.878%** | 41.8% |

**峰值在 2~3%，然后单调衰减，7% 以上直接翻负。** 原策略用「越高越好」的单调评分，方向刚好和真实规律相反——它把最高分给了最差的区间。

### 4. 这个规律稳不稳定

按月拆开看，统计各区间「正收益月份占比」：

| 区间 | 正收益月份 | 占比 |
|---|---|---|
| 0~1% | 29/47 | 61.7% |
| 1~2% | 28/47 | 59.6% |
| **2~3%** | **26/35** | **74.3%** |
| 3~5% | 23/38 | 60.5% |
| 5~7% | 16/27 | 59.3% |
| **7~10%** | **8/25** | **32.0%** |

- **7~10% 只有 32% 的月份为正**——这是本报告里最稳的结论：高开过度就是坑
- **2~3% 有 74.3% 的月份为正**——相对稳定，但样本月份只有 35 个
- 其余区间在 59~62%，**接近抛硬币**

注意 2026-07 和 2026-10 两个月所有区间全线大亏（7~10% 区间当月 -4.04% 和 -1.40%），说明这类策略在市场急跌时没有防御性。

---

## 三、这个结论能用到什么程度

### 可以说的

1. **「买竞价高开、按涨幅越高越好排序」是无效的**，464 个交易日、280 万样本支持这个判断
2. **7% 以上是明确的负区间**，25 个月里 17 个月亏，这个结论足够稳
3. **2~5% 是相对好的区间**，但超额很薄：2~3% 区间日均 +0.337%，扣掉全市场基准 +0.166%，净超额只有 +0.17%，再扣交易成本（佣金+印花税+滑点约 0.15%）基本不剩
4. 原策略那个 **7% 上限是对的**（<7% 比 <9.5% 好 1 个百分点/天），但它是从「怕追高」的经验来的，方向对了，评分逻辑仍错

### 不能说的

1. **没验证完整综合分。** 综合分有 6 个因子，历史数据只能重建「竞价涨幅」一个。竞价量、量比、警示类型、历史流通市值东财都不提供历史值；「今日涨幅」在 9:25 时还没产生，用它选股是偷看未来
2. **没有回测「2~3% 甜点区 + 量能」的组合。** 这是可能的改进方向，但没测过，不能宣称有效
3. **样本只有 2 年。** 单个牛熊周期，跨周期表现未知
4. **有幸存者偏差。** 库里只有现存股票，退市的没算进来
5. **没计交易成本。** 上面所有数字都是毛收益，实际要再减约 0.15%/次往返

---

## 四、如果要改，方向是什么

基于上面的数据，有依据的改动只有一个：

**把竞价涨幅的评分从「单调递增」改成「倒 U 型」**，峰值落在 2~3%，5% 以上开始扣分，7% 以上直接剔除（原策略已经有 7% 上限，保留）。

但这只解决了 0.32 那一项权重。**其余 68% 的权重所依赖的因子，历史数据都验证不了。** 所以即使改完，也不等于「策略能赚钱」——只能说「不再把最高分给最差的一档」。

**我的判断：这个工具适合当「看盘辅助」，不适合当「选股信号源」。**

如果要做成有统计依据的选股信号，得先解决数据问题（历史竞价量、量比、真竞价快照），那需要付费数据源或者自己每天积累快照。现在这套免费接口做不到。

## 五、怎么复现

```bash
cd backtest

# 1. 抓数据（约 4 分钟，58MB/250天 或 116MB/500天）
python3 fetch_daily.py --workers 10 --days 500

# 2. 跑回测（T+1 可执行口径）
python3 run_backtest.py --top 3,10,20 --min-pool 1000 --hold 1

# 3. 指定竞价涨幅上限（模拟原策略阈值）
python3 run_backtest.py --bid-cap 7 --hold 1

# 4. 时间稳定性检验
python3 stability.py
```

`--hold` 参数：
- `0` = D 日收盘卖（T+1 下不可执行，仅作对照）
- `1` = D+1 日收盘卖（默认，可执行）
- `2` = D+1 日开盘卖（可执行）

由于行情每天都在变，重跑的具体数字会略有差异，但结论方向稳定。
